# M39.2.4 SDK Flange Alignment Test

## Goal

M39.2.4 isolates the remaining fixed tool-frame error after the 24-sample PARK
Eye-to-Hand calibration has been deployed in `robot_default_base`.

The production visual chain currently computes `hand_tcp_link` correctly enough
to test, but the configured `hand_tcp_to_flange` transform is still the old
URDF/installation assumption. The robot SDK pose used for comparison is treated
as the LEFT SDK flange pose returned by:

```python
robot.motion.get_pose(ArmType.Left)
```

M39.2.4 estimates the fixed transform:

```text
T_hand_tcp_sdk_flange
  = inv(T_base_hand_tcp_visual) @ T_base_sdk_flange_actual
```

This phase is **test-only**. It does not modify online production flange output.

## Why clock=1 is locked during calibration

The six previous manual samples show a strong fixed component, but clock=3 is
not consistent with the clock=1 cluster. To avoid fitting clock-dependent visual
grasp orientation error into a supposedly fixed tool transform, the calibration
set uses only one clock direction first. Default is clock=1.

## Files added/changed

- `scripts/test_m39_2_4_sdk_flange_alignment.py`
  - validates online service is `robot_default_base / PARK / PASS / 24`;
  - accepts only the configured clock hour (default 1);
  - uses **visual hand_tcp**, not the current legacy flange estimate, as fit input;
  - asks for the actual SDK LEFT flange pose;
  - computes one `T_hand_tcp_sdk_flange` per sample;
  - saves JSONL/CSV and updates a running fixed-transform fit;
  - optionally loads a previous fit with `--trial-transform` for independent validation.
- `scripts/test_m39_2_visual_grasp_pose.py`
  - stale-service guard updated to `robot_default_base / PARK / PASS / 24` so an
    old ANDREFF/base_link service cannot silently produce comparison samples.

## Phase A: collect 8-12 clock=1 calibration samples

On RK3576:

```bash
cd /opt/visionops_v3
python3 production/foam_ring_grasp/scripts/test_m39_2_4_sdk_flange_alignment.py
```

For each accepted visual trigger:

1. The script checks:
   - left arm;
   - `base_frame_id == robot_default_base`;
   - `selected_method == PARK`;
   - `quality_status == PASS`;
   - `sample_count_used == 24`.
2. It checks `selected_clock_hour == 1`.
   - If not 1, the sample is skipped before manual robot pose input.
3. Manually align the physical gripper to the visual target.
4. Read the robot SDK flange pose from `robot.motion.get_pose(ArmType.Left)`.
5. Paste seven values:

```text
X Y Z QX QY QZ QW
```

Default XYZ input unit is meters, matching the SDK.

Use 8-12 samples distributed across the actual box workspace (left/middle/right,
near/middle/far), while keeping clock=1.

## Outputs

Default directory:

```text
/opt/visionops_v3/m39_2_4_sdk_flange_alignment/
```

Files:

```text
m39_2_4_samples.jsonl
m39_2_4_samples.csv
m39_2_4_sdk_flange_fit.json
raw/*.json
```

After each accepted manual sample, a running fit is printed:

```text
T_hand_tcp_sdk_flange_mm
translation median
rotation quaternion average
fit translation mean/p95/max
fit rotation mean/p95/max
```

The fit uses component-wise median translation and quaternion/chordal rotation
averaging to reduce the influence of a few millimetres of manual positioning
error.

The generated fit is explicitly marked:

```text
TEST_ONLY_NOT_FOR_PRODUCTION
```

Do not copy it into `line.yaml` yet.

## Recompute fit without triggering vision

```bash
python3 production/foam_ring_grasp/scripts/test_m39_2_4_sdk_flange_alignment.py \
  --fit-only
```

## Phase B: independent trial validation

After 8-12 calibration samples, keep the generated fit file fixed and collect a
**new set** of poses:

```bash
python3 production/foam_ring_grasp/scripts/test_m39_2_4_sdk_flange_alignment.py \
  --out-dir m39_2_4_sdk_flange_validation \
  --trial-transform m39_2_4_sdk_flange_alignment/m39_2_4_sdk_flange_fit.json
```

The script prints:

```text
TRIAL SDK flange
trial position error
trial orientation error
```

This corrected pose is computed only inside the test helper:

```text
T_base_sdk_flange_trial
  = T_base_hand_tcp_visual @ T_hand_tcp_sdk_flange_trial
```

The online service is not modified.

## Decision rule

Do not promote a transform based only on the fit residual of the same samples.
Promotion requires a separate validation set. The first goal is to confirm that
clock=1 drops from roughly tens of millimetres / ~150 deg to a repeatable small
residual. Only then should the fitted transform replace the legacy production
`hand_tcp_to_flange` transform.

After clock=1 is closed, clock=2/3 are tested separately. If they remain biased,
fix the Visual Grasp Frame clock orientation construction rather than creating a
different physical tool transform per clock direction.
