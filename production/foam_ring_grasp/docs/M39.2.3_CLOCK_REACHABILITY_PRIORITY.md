# M39.2.3 Clock Reachability Priority

## Goal

For the current LEFT-arm installation, manually verified 1~3 o'clock rim-pinch
clock directions are easier for the robot to reach. M39.2.3 adds a visual-side
reachability prior without weakening any geometry, box-wall, neighbor, full
static-gripper, motion, or robot-safe-tilt gate.

## Policy

`clock_search.preferred_clock_hours: [1, 2, 3]`

Selection is now lexicographic among candidates that already pass their current
evaluation stage:

1. preferred 1~3 o'clock direction;
2. existing geometry/collision score.

The preferred directions are also promoted into the primary adaptive search
batch, so 1 o'clock is no longer deferred behind a successful non-preferred
primary direction.

For M38.1 Branch-A, `compare_top_clock_candidates: 3` therefore normally causes
1/2/3 o'clock to receive full collision evaluation first when all three are
light-valid. The best valid candidate inside that preferred group is selected.
If none of the preferred directions is valid, the existing remaining clock
positions continue to be evaluated as fallback.

## Safety

This is not an IK/reachability solver. Preferred directions never bypass:

- 2-D boundary validity;
- 3-D box-wall checks;
- neighbor 3-D checks;
- complete static gripper checks;
- configured motion checks;
- `robot_safe_max_tilt_deg`.

A preferred direction that is invalid or colliding is rejected exactly as
before.

## Diagnostics

Scene/service output now exposes:

- `preferred_clock_hours`;
- `selected_clock_preferred`;
- `robot_candidate.target.clock_preferred`.

The manual M39.2 pose sampling script also prints the selected clock and whether
it belongs to the preferred group.
