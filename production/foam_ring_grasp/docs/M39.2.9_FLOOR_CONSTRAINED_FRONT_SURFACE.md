# M39.2.9 Floor-Constrained 2.5-D Front Surface

## Why M39.2.9 replaces the M39.2.7 / M39.2.8 production normal logic

Real production replay showed that the Branch-A annulus depth is useful for **front-height**
estimation, but unreliable for unconstrained normal estimation.

- M39.2.7 could preserve a false measured normal once the measured-vs-floor disagreement
  exceeded the old threshold, so flat rings occasionally became visibly tilted.
- M39.2.8 removed that angular switch and introduced equal-sector measured-vs-floor plane
  competition, but real Orbbec depth-edge / inner-wall contamination made the equal-sector
  plane-quality gate too brittle. Normal flat rings were falsely rejected, while some sparse
  measured hypotheses still produced 20-40 degree false tilts.
- Raw `exact_depth.png` from the problem set still showed a strong physical signal: the ring
  front and the deeper wall/floor were typically separated by about 50-80 mm. The sensor can
  therefore locate the front surface well even when it cannot estimate a few-degree plane
  normal reliably from the annulus boundary.

M39.2.9 changes the model rather than loosening M39.2.8 thresholds.

## Branch-A information ownership

```text
RGB segmentation
    -> ring/mouth identity, 2-D opening boundary, clock direction

calibrated box model
    -> Branch-A normal / approach direction

raw depth
    -> camera-near front-layer selection
    -> observed ring-front height only

3-D depth / box / neighbor / gripper models
    -> collision and safety
```

The Branch-A final plane is therefore:

```text
normal = calibrated box-floor normal toward camera
offset = robust observed ring-front height
```

This is a 2.5-D model: the orientation is constrained by known fixture geometry while the
surface depth remains measured from the current RGB-D frame.

## 1-D front-layer separation

M39.2.9 projects annulus points onto the calibrated box `+Z_inside` axis and performs a
robust deterministic two-center split. A split is applied only when:

- center separation >= `24 mm`;
- both layers contribute >= `8%` of the annulus points; and
- the camera-near layer contains >= `80` points.

Unlike M39.2.2's largest sorted-gap detector, the two-center model tolerates a short depth
transition tail between the front face and the inner-wall / floor layer.

If there is no strong two-layer split, all already edge-filtered annulus points continue to
height estimation. This is not a rejection condition.

## Sector-balanced height, not sector-balanced normal

The M39.2.8 sector idea is retained but assigned a narrower responsibility.

For each angular sector:

1. require at least 5 points;
2. compute the median coordinate along the final floor normal;
3. compute the median and MAD across sector heights;
4. reject sector-height outliers;
5. use the median of good sector medians as the front-surface offset.

The outlier threshold is:

```text
max(5 mm, 3 * 1.4826 * MAD), capped at 20 mm
```

A dense local crescent therefore cannot dominate the height, while a few bad D2C / inner-wall
sectors do not reject the whole opening.

If fewer than four good sectors remain, M39.2.9 can fall back to a trimmed point median. This
fallback is a height estimator only; it does not estimate a normal.

## Measured plane is diagnostic only

A legacy point-level RANSAC plane is still calculated when enabled, but it cannot change:

- final normal;
- inner / outer rim 3-D points;
- contact positions;
- approach direction;
- closing axis;
- collision volumes; or
- LEFT_LINK7 pose.

It is emitted as:

```text
m38_branch_a.front_surface.measured_plane_diagnostic
```

with `measured_vs_floor_deg` and a status:

- `depth_normal_consistent`
- `depth_normal_unreliable`
- `depth_normal_severely_unreliable`

This makes a false 20-40 degree measured normal visible in logs without allowing it to rotate
the robot grasp.

## Production configuration

```yaml
branch_a_front_surface:
  enabled: true
  mode: floor_constrained
  reference: calibrated_box_floor
  require_reference: true

  depth_layer:
    kmeans_iterations: 24
    minimum_center_gap_mm: 24.0
    minimum_layer_fraction: 0.08
    minimum_near_points: 80

  height_estimation:
    sector_count: 16
    minimum_sector_points: 5
    minimum_good_sectors: 4
    preferred_good_sectors: 6
    minimum_height_outlier_threshold_mm: 5.0
    maximum_height_outlier_threshold_mm: 20.0
    mad_scale: 3.0
    point_fallback_enabled: true
    minimum_point_fallback_count: 60
    point_trim_low_percentile: 10
    point_trim_high_percentile: 90
    plane_inlier_threshold_mm: 8.0

  measured_plane_diagnostic:
    enabled: true
    warning_disagreement_deg: 10.0
    severe_disagreement_deg: 20.0
```

The historical M39.2.8 selector remains in the file for replay compatibility but is disabled:

```yaml
annulus_plane_selection:
  enabled: false
```

## Final geometry chain

```text
foam_ring + ring_mouth
    -> strict association / ellipse quality
    -> annulus mask
    -> depth-edge + neighbor-mask exclusion
    -> raw annulus 3-D points
    -> box-normal 1-D near/far layer separation
    -> sector-balanced robust front height
    -> FINAL floor-constrained plane
    -> mouth-center ray / inner-rim ray / outer-rim ray intersections
    -> closing axis projected in final plane
    -> approach = -final normal = box +Z_inside
    -> contact / pregrasp / grasp
    -> box / neighbor / gripper-static / motion collision
    -> camera grasp frame
    -> robot_default_base / LEFT_LINK7 transform
```

All XYZ and orientation values therefore consume the same final plane.

## Real 14-frame M39.2.8 failure-set replay

The supplied 14 captures were confirmed to contain flat rings. Replaying them with the
M39.2.9 production config produced:

```text
bundle count                 : 14
target found                 : 14 / 14
front-surface model pass     : 14 / 14
max final normal vs floor    : 0.0 deg
max diagnostic measured-floor: 40.6705 deg
```

The final camera tilt is the calibrated box-floor tilt relative to camera Z (`1.8861 deg`) in
all 14 frames. The old measured plane can still report a false ~40 degree tilt, but it remains
diagnostic only.

Run the same replay with:

```bash
python3 production/foam_ring_grasp/scripts/replay_m39_2_9_floor_constrained.py \
  /path/to/foam_ring_online_geometry \
  --require-target \
  --output /tmp/m39_2_9_replay
```

## Synthetic regression

```bash
python3 production/foam_ring_grasp/scripts/test_m39_2_9_floor_constrained_front_surface.py
```

Expected output includes:

```text
M39.2.9 synthetic front-surface regression: PASS
```

It protects three behaviors:

1. a clear near/far ring-front versus floor layer is separated;
2. a badly tilted measured RANSAC normal cannot rotate the final plane; and
3. several strongly polluted angular sectors cannot move the robust front height.
