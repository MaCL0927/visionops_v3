# M39.2.7 Clock-3 Canonical Orientation + Flat-Ring Normal Stabilization

## Scope

M39.2.7 fixes two issues isolated by the M39.2.6 robot trials:

1. **Manual clock-3 SDK-flange validation was still polluted by per-frame ring tilt.**
   The visual grasp XYZ was usable, but the ring plane normal varied by about 0.9~8.5 deg across physically flat placements.
2. **Production branch-A flat rings inherited that same raw annulus-normal drift.**
   With a ~168 mm hand-TCP-to-flange lever arm, several degrees of false tilt become centimeter-scale flange XYZ error.

The fixed hand-TCP -> SDK flange transform from the 10-sample robust clock-3 fit is also promoted into both M39.2.7 configs:

```text
T_hand_tcp_sdk_flange_mm =
[ 0.995921716 -0.087619482  0.021511897 -164.567832 ]
[-0.089118123 -0.992545706  0.083132319   -3.149675 ]
[ 0.014067531 -0.084710381 -0.996306306   35.546126 ]
[ 0            0            0              1          ]
```

Transform direction is unchanged:

```text
T_base_sdk_flange = T_base_hand_tcp @ T_hand_tcp_sdk_flange
```

## A. Clock-3 calibration mode

Use:

```text
production/foam_ring_grasp/config/line_clock3_calibration.yaml
```

This mode keeps the measured visual **grasp-center XYZ** unchanged, but overrides only the emitted grasp-frame orientation:

```text
clock 3 closing +X = camera optical +X
approach       +Z = camera optical +Z
```

This is deliberate: the robust tool-TF was fitted with the same camera-axis canonical definition and the operator's clock-3 manual alignment is an exact 90-degree image/camera reference.

The candidate JSON now reports:

```text
gr​asp_frame_camera.orientation_policy = canonical_clock_camera_axes
```

and includes `orientation_diagnostics`, including the rotation removed from the raw measured ring plane.

The M39.2.4 helper now defaults to requiring this policy. If the online service is accidentally started with the production config, the helper refuses the calibration sample instead of silently mixing raw tilt back into the fit.

## B. Production flat-ring normal stabilization

Normal production still uses:

```text
production/foam_ring_grasp/config/line.yaml
```

M39.2.7 adds:

```yaml
flat_ring_normal_stabilization:
  enabled: true
  reference: calibrated_box_floor
  pose_strategies: [m38_1_front_annulus]
  snap_max_reference_disagreement_deg: 9.0
  preserve_measured_at_reference_disagreement_deg: 12.0
```

The calibrated shallow-box +Z axis points from the opening into the box. Therefore the flat-ring normal toward the camera is `-box_z_inside`.

Policy:

- raw-vs-box disagreement <= 9 deg: snap to box-floor normal;
- 9~12 deg: blend smoothly from box-floor reference toward the measured normal;
- >= 12 deg: preserve measured normal;
- branch-B/side-ring geometry is never flattened by this logic.

Only orientation is stabilized. The plane offset is re-anchored to the observed front-ring depth points, so ring depth/XYZ is not replaced by a nominal box height.

The calibrated box in this deployment is tilted about **1.886 deg** relative to the camera optical axis. Therefore a correctly stabilized flat ring should report about 1.886 deg camera tilt, not 0 deg.

## M39.2.6 five-frame replay

The five independent robot-test frames that exposed the problem had raw branch-A tilts:

```text
1.369, 1.222, 0.869, 8.468, 4.649 deg
```

With M39.2.7 production stabilization they all snap to the same calibrated box-floor orientation:

```text
1.886 deg
```

All five still produce a valid robot candidate; normal production clock selection remains 2/3 priority.

For an apples-to-apples replay against the operator's clock-3 manual poses, the M39.2.7 calibration config gives:

```text
position error:    mean 5.99 mm, p95 8.20 mm, max 8.40 mm
orientation error: mean 0.334 deg, p95 0.432 deg, max 0.444 deg
```

This is the expected validation path for the corrected fixed tool transform.

## Deployment

Production:

```bash
bash production/foam_ring_grasp/scripts/start_online_service.sh
```

Clock-3 manual validation:

```bash
VISIONOPS_FOAM_RING_CONFIG=/opt/visionops_v3/production/foam_ring_grasp/config/line_clock3_calibration.yaml \
  bash production/foam_ring_grasp/scripts/start_online_service.sh
```

Then:

```bash
python3 production/foam_ring_grasp/scripts/test_m39_2_4_sdk_flange_alignment.py \
  --out-dir m39_2_7_clock3_validation
```

Expected header:

```text
calibration lock: clock=3
orientation lock: canonical_clock_camera_axes
```

For general pose comparison:

```bash
python3 production/foam_ring_grasp/scripts/test_m39_2_visual_grasp_pose.py
```

The service summary now includes raw/output tilt and the grasp orientation policy so configuration mistakes are visible immediately.
