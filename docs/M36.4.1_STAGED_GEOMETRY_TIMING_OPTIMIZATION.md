# M36.4.1 分段计时与候选分级计算优化

## 1. 背景

M36.4 已证明以下在线链路正确：

```text
RKNN segmentation polygon
  -> capture_timestamp_ms
  -> exact RGB-D cache match
  -> SegmentationInstance
  -> analyze_scene()
```

真机单帧结果中，Runtime 推理约 64 ms，但 `analyze_scene()` 约 14.9 s。原实现会对每个成功配对圆环的 12 个钟点候选全部执行：

- 3-D 箱壁扫掠；
- 邻环深度点云碰撞；
- 完整夹爪最终位姿静态碰撞；
- 可选的完整预抓取运动碰撞。

5 个配对意味着 60 个完整候选，适合离线诊断，不适合在线处理。

## 2. 两种运行模式

### staged（在线默认）

1. 所有配对先完成椭圆、深度点、RANSAC 平面、姿态和物理尺寸检查；
2. 每个未提前拒绝的配对生成 12 个轻量候选；
3. 轻量候选只计算边界、指爪二维扫掠、开口、图像边界、二维邻接和局部深度；
4. 按顶层、倾角、轻量得分、置信度和深度排序；
5. 以配对 round-robin 方式避免预算集中在同一个圆环；
6. 默认先对 4 个候选执行完整 3-D 碰撞；有效候选不足时最多扩展到 8 个；
7. 只有完整检查通过的候选才可成为 `best_clock_candidate`。

### exhaustive（诊断兼容）

保留原逻辑：所有配对的 12 个钟点全部执行完整检查。该模式用于 A/B 对照，不建议持续在线运行。

## 3. 无损计算复用

M36.4.1 同时加入两项不会削弱判定范围的复用：

- 每个 ring mask 的 Depth -> 3-D 基础点云每帧只构建一次；
- 每个目标的 `other_ring_mask` 距离变换只计算一次，12 个钟点共享。

目标平面相关的重复表面排除仍在每个目标上独立执行，不会把一个目标的平面过滤结果错误复用给另一个目标。

## 4. 配置

```yaml
geometry_optimization:
  enabled: true
  mode: staged
  timing_enabled: true
  skip_rejected_pairs: true
  prefer_top_layer: true
  round_robin_pairs: true
  cache_neighbor_point_clouds: true
  initial_full_candidate_budget: 4
  maximum_full_candidate_budget: 8
  minimum_valid_full_candidates: 2
  expand_if_no_valid: true
```

说明：

- `initial_full_candidate_budget`：无论是否已找到有效候选，至少检查的完整候选数量；
- `maximum_full_candidate_budget`：完整检查硬上限；
- `minimum_valid_full_candidates`：达到初始预算后，希望至少保留的完整有效候选数；
- `expand_if_no_valid`：初始预算没有有效候选时，是否继续扩展；
- `round_robin_pairs`：先从不同配对各取一个高分候选，再取第二轮，避免全部预算落到一个目标。

## 5. 真机运行

默认使用 `line.yaml` 的 staged 模式：

```bash
cd /opt/visionops_v3
bash production/foam_ring_grasp/scripts/run_online_geometry_once.sh
```

强制 staged：

```bash
VISIONOPS_FOAM_RING_GEOMETRY_MODE=staged \
  bash production/foam_ring_grasp/scripts/run_online_geometry_once.sh
```

强制 exhaustive：

```bash
VISIONOPS_FOAM_RING_GEOMETRY_MODE=exhaustive \
  bash production/foam_ring_grasp/scripts/run_online_geometry_once.sh
```

也可以直接使用：

```bash
python3 -m production.foam_ring_grasp.tasks.foam_ring_grasp_vision.online_validate \
  --geometry-mode staged
```

`online_geometry_result.json` 新增：

```text
scene.timing_ms
scene.timing_detail.pairs
```

候选完整检查的主要分段包括：

## 7. 验收建议

先连续运行 5~10 次 staged，检查：

- `full_candidate_evaluated_count` 是否通常为 4~8；
- `full_candidate_valid_count` 是否至少为 1；
- `selected_ring_instance_id`、`selected_clock_hour` 是否稳定；
- `full_gripper_static_ms`、`neighbor_3d_ms` 哪一项占主要耗时；
- `geometry_ms` 是否较 M36.4 的约 14.9 s 明显下降。

随后在场景静止时各运行一次 staged 与 exhaustive，比较：

- 最终选中 ring；
- 最终 clock；
- 候选拒绝原因；
- 箱壁、邻环、完整夹爪静态碰撞状态。

staged 是预算搜索，不保证与 exhaustive 在所有复杂场景下绝对相同。若 staged 经常预算耗尽且没有有效候选，应先把 `maximum_full_candidate_budget` 从 8 提高到 10 或 12，而不是关闭完整碰撞检查。
