# M32.4 Web 输入 ROI 可视化（第四阶段）

M32.4 建立在 M32.3.1 Runtime 高性能输入 ROI 之上，只修改 Collector Web 和模型目录摘要，不改变 Runtime 推理、机器人协议或结果 ROI 接口。

## 1. 完整图上的两类 ROI

模型验证页和生产模式的完整视频画面现在同时支持：

- 青色实线：`preprocess.input_roi`，表示真正送入模型的图像区域；
- 黄色虚线：原有 `/api/runtime/roi`，只过滤最终输出结果；
- 检测框、OBB、分割轮廓和业务抓取点仍使用完整图坐标绘制。

输入 ROI 标签会显示：

```text
模型输入 ROI 427×229 → 640×640
```

## 2. 模型实际输入预览

模型验证页和生产模式新增“模型输入预览”按钮。开启后，右侧显示浏览器根据当前完整快照、`input_roi.pixel_xyxy`、模型输入尺寸及 Runtime letterbox 参数复现出的模型输入图。

该预览：

- 复用已经获取的完整快照；
- 不请求第二张图片；
- 不调用 Runtime infer_once；
- 不增加 NPU 工作；
- 不改变正式 RGA crop + resize 路径。

预览画布优先使用结果中的 `debug.letterbox.scale_x/scale_y/pad_x/pad_y`，调试字段缺失时按模型输入尺寸重新计算 letterbox。

## 3. ROI 性能诊断条

模型验证页和生产画面增加六项状态：

- 模型输入 ROI；
- 模型输入尺寸；
- 预处理后端；
- ROI 解析耗时；
- 裁剪 + 缩放耗时；
- NPU 推理耗时。

当 Runtime 返回：

```json
{
  "rga_used": true,
  "rga_fused_crop_resize": true
}
```

Web 显示“RGA 融合裁剪”。若 RGA 回退并返回 `preprocess_warning`，诊断条切换为警告样式并展示原因。

## 4. 模型列表 ROI 摘要

Collector 扫描 `model.yaml` 时会读取：

```yaml
preprocess:
  input_roi:
```

模型列表新增“输入 ROI”字段，例如：

```text
427×229 @ 1280×720
```

旧模型或 `enabled: false` 显示“全画面”。

## 5. 兼容性

- 不修改 `angle_deg`、`center_px`、`obb_points` 等机器人字段；
- 不修改原有结果 ROI 字段和接口；
- 旧模型无 `input_roi` 时仍可显示全画面模型输入预览；
- Detection、OBB、Segmentation 和 Classification 共用同一输入 ROI 显示逻辑；
- 生产业务 App 的 `visualization_result` 是 Runtime 结果的深拷贝，因此输入 ROI、timing 和 debug 字段可以直接显示。

## 6. 更新

M32.4 仅修改 Python/HTML/CSS/JavaScript，不需要重新编译 C++ Runtime。

覆盖代码后重启 Collector：

```bash
sudo systemctl restart visionops-v3-detergent-grasp-collector.service
```

若使用通用 Collector 服务，替换为现场实际服务名。

浏览器建议执行强制刷新：

```text
Ctrl + Shift + R
```

## 7. 验证

1. 切换到带 `preprocess.input_roi.enabled: true` 的模型；
2. 在模型验证页执行一次“拍照检测”；
3. 完整图中应看到青色输入 ROI；
4. 点击“模型输入预览”，应看到 ROI 裁剪和灰色 letterbox；
5. 检查诊断条是否显示 `RGA 融合裁剪`；
6. 原有黄色结果 ROI 仍可独立绘制、启用和关闭；
7. 进入生产模式，确认相同信息持续更新。
