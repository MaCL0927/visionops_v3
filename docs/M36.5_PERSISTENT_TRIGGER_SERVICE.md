# M36.5：泡沫圆环常驻触发式在线服务

M36.5 将 M36.4.2 的单次命令封装为常驻 HTTP 服务。服务启动后只初始化一次：

- Orbbec 336L 精确同步 RGB-D 短时缓存；
- C++ RKNN Runtime Raw Local HTTP 客户端；
- `line.yaml` 几何配置；
- 3D 箱体标定模型；
- `first_valid + adaptive_8_plus_4` 抓取策略。

每次显式触发仍然执行严格事务：

```text
request_id
  → Runtime infer_once
  → capture_timestamp_ms
  → 精确匹配同时间戳 RGB-D
  → polygon 栅格化
  → first_valid 三维几何
  → 返回一个相机坐标系抓取候选
```

找不到完全相同时间戳的深度、Runtime 回退 HTTP JPEG、出现 bbox fallback 或 D2C/内参异常时，本次请求失败，不使用最新深度替代。

## 1. 启动

保持 Orbbec Bridge 与圆环 RKNN Runtime 正常运行，然后：

```bash
cd /opt/visionops_v3
bash production/foam_ring_grasp/scripts/start_online_service.sh
```

默认监听：

```text
0.0.0.0:19213
```

环境变量覆盖：

```bash
export VISIONOPS_FOAM_RING_LISTEN_HOST=0.0.0.0
export VISIONOPS_FOAM_RING_LISTEN_PORT=19213
export VISIONOPS_FOAM_RING_RUNTIME_URL=http://127.0.0.1:28081
export VISIONOPS_FOAM_RING_GEOMETRY_MODE=first_valid
```

## 2. 健康与状态

```bash
curl -s http://127.0.0.1:19213/health | python3 -m json.tool
curl -s http://127.0.0.1:19213/status | python3 -m json.tool
```

健康状态同时检查：

- RGB-D Cache 线程；
- Runtime segmentation 模型；
- Runtime RGB 实际传输是否为 `posix_shared_memory`；
- inference worker 与 geometry worker 是否存活；
- 当前是否 busy 与最近错误。

`/status` 额外返回：

- 可靠触发队列大小；
- request registry 状态；
- accepted/completed/failed/duplicate 计数；
- 处理耗时 p50/p95；
- RGB-D cache FPS、exact match 计数；
- 最近一次触发结果。

## 3. 同步显式触发

```bash
curl -s -X POST http://127.0.0.1:19213/api/foam_ring/infer_once \
  -H 'Content-Type: application/json' \
  -d '{
    "request_id": "robot-000001",
    "wait": true,
    "timeout_ms": 15000,
    "save_debug": false
  }' | python3 -m json.tool
```

成功返回：

```json
{
  "message_type": "foam_ring_trigger_result",
  "status": "ok",
  "request_id": "robot-000001",
  "target_found": true,
  "robot_ready": false,
  "capture_timestamp_ms": 1785785137549,
  "rgbd_timestamp_delta_ms": 0,
  "scene_summary": {
    "matched_pairs": 1,
    "selected_ring_instance_id": 0,
    "selected_clock_hour": 5,
    "selected_clock_angle_deg_cw_from_12": 150.0
  },
  "candidate": {},
  "timing_ms": {}
}
```

M36.5 只返回相机坐标系候选，仍保持 `robot_ready=false`。M37 已用于侧躺圆环参数化模板分支；手眼变换、机器人可达性和正式机器人协议放到后续机器人集成阶段。

## 4. 可靠 request_id

显式触发不使用 latest-only 队列。服务使用双线程可靠流水线：

- 一个 Runtime inference worker；
- 一个串行 geometry worker；
- 有界触发队列与有界 geometry 队列；
- 有界 request registry；
- request_id 幂等回放。

相同 `request_id` 再次提交时：

- queued/running：返回同一任务状态；
- completed：返回原结果，`idempotent_replay=true`；
- 不会重新触发 Runtime；
- 不会被后续请求覆盖。

异步提交：

```bash
curl -s -X POST http://127.0.0.1:19213/api/foam_ring/infer_once \
  -H 'Content-Type: application/json' \
  -d '{"request_id":"robot-000002","wait":false}' | python3 -m json.tool
```

查询：

```bash
curl -s http://127.0.0.1:19213/api/foam_ring/request/robot-000002 \
  | python3 -m json.tool
```

触发队列满时返回 HTTP 429 `TRIGGER_QUEUE_FULL`，已有显式任务仍被保留。Inference worker 在取得 Runtime 原始结果后会立即复制精确同帧 RGB-D 和 mask，再送入 geometry 队列，因此后续缓存淘汰不会破坏已接收请求。

## 5. 生产模式与调试保存

默认：

```yaml
online_service:
  default_save_debug: false
```

普通触发不创建 RGB、Depth、JSON 或 overlay 文件，减少约数百毫秒的落盘开销。

仅诊断请求显式设置：

```json
{"request_id":"debug-001","save_debug":true}
```

才保存：

```text
data/foam_ring_online_geometry/<capture_timestamp_ms>/
├── exact_rgb.png
├── exact_depth.png
├── depth_colormap.jpg
├── runtime_inference_result.json
├── online_geometry_overlay.jpg
└── online_geometry_result.json
```

## 6. 最近结果和叠加图

```bash
curl -s http://127.0.0.1:19213/api/foam_ring/latest_result \
  | python3 -m json.tool

curl -s http://127.0.0.1:19213/snapshot.jpg \
  -o /tmp/foam_ring_latest.jpg
```

叠加图只在触发完成后更新，不进行连续三维推理或持续磁盘写入。

## 7. 验收

```bash
cd /opt/visionops_v3
python3 production/foam_ring_grasp/scripts/verify_online_service.py \
  --samples 5 \
  --report /tmp/m36_5_report.json
```

验收检查：

- `/health=ok`；
- 每个 request_id 获得唯一结果；
- RGB-D 时间差始终为 0；
- 默认触发不落盘；
- duplicate request_id 不重新推理；
- `/snapshot.jpg` 可读取；
- RGB-D Cache 保持约 30 FPS；
- 输出服务触发延迟 mean/p50/p95/max。

调试保存抽查：

```bash
python3 production/foam_ring_grasp/scripts/verify_online_service.py \
  --samples 5 \
  --save-debug-once \
  --report /tmp/m36_5_debug_report.json
```
