# M32.2 服务端采集 ROI 元数据传递

M32.2 完成输入 ROI 的第二阶段：服务端只传递、校验和写入部署配置，暂不改变边缘 Runtime 的取图与推理路径。

## 数据流

```text
M32.1 capture_manifest.json
    -> server batch.json
    -> dataset.json + capture_metadata.json
    -> training job_config.json
    -> preprocess_report.json
    -> package.json
    -> model.yaml / preprocess.input_roi
```

原有结果过滤 ROI 仍使用边缘 Runtime 的 `roi` 配置，本阶段没有修改其字段或语义。

## 上传包接收

服务端优先读取压缩包根目录的 `capture_manifest.json`，同时兼容 `manifest.json.capture`。启用 ROI 时会校验：

- `images_are_cropped=true`；
- `source_resolution` 有效；
- `pixel_xyxy` 位于源图范围内；
- `normalized_xyxy` 与像素坐标一致；
- `crop_resolution` 与像素边界一致；
- 默认补充 `resize_mode=letterbox`、`pad_value=114`。

没有 M32.1 元数据的旧包按完整图处理：

```json
{"enabled": false}
```

如果元数据文件存在但格式错误，上传包会处理失败，不会静默退回完整图。

## 多包和多 batch 约束

一个训练模型只能携带一套生产输入 ROI，因此：

- 多个包 ROI 完全一致：允许合并；
- 多个包均为完整图：允许合并；
- ROI 坐标不同：拒绝；
- 完整图与 ROI 图混合：拒绝；
- 源分辨率、坐标空间、resize_mode 或 pad_value 不同：拒绝。

校验在修改 batch 状态、创建 dataset 目录之前完成，避免生成半成品数据集。

## batch 元数据

`server_data/batches/<batch_id>/batch.json` 新增：

```json
{
  "capture_manifest_path": ".../raw/capture_manifest.json",
  "capture_manifest": {},
  "capture_metadata": {},
  "images_are_cropped": true,
  "input_roi": {
    "enabled": true,
    "coordinate_space": "runtime_snapshot",
    "source_resolution": {"width": 1280, "height": 720},
    "pixel_xyxy": [320, 144, 960, 576],
    "normalized_xyxy": [0.25, 0.2, 0.75, 0.8],
    "crop_resolution": {"width": 640, "height": 432},
    "resize_mode": "letterbox",
    "pad_value": 114
  }
}
```

## dataset 元数据

数据集目录新增：

```text
server_data/datasets/<dataset_id>/capture_metadata.json
```

`dataset.json` 同时保存 `input_roi`、`images_are_cropped`、`source_capture_metadata` 和 `capture_metadata_json`，训练任务直接引用该数据集元数据。

## 训练任务

`job.json` 和 `job_config.json` 自动继承：

```json
{
  "images_are_cropped": true,
  "input_roi": {},
  "capture_metadata": {},
  "capture_metadata_json": ".../capture_metadata.json"
}
```

训练图片已经是 ROI 裁剪图，训练本身不再二次裁剪。`preprocess_report.json` 只记录同一套 ROI，供模型打包阶段使用。

## model.yaml

模型包新增：

```yaml
preprocess:
  input_roi:
    enabled: true
    coordinate_space: runtime_snapshot
    source_resolution:
      width: 1280
      height: 720
    pixel_xyxy: [320, 144, 960, 576]
    normalized_xyxy: [0.25, 0.2, 0.75, 0.8]
    crop_resolution:
      width: 640
      height: 432
    resize_mode: letterbox
    pad_value: 114
```

旧的运行时预处理字段仍保留：

```yaml
runtime:
  preprocess: letterbox
  color: rgb
```

二者含义不同：

- `preprocess.input_roi`：第三阶段由 Runtime 用来裁剪完整相机帧；
- `runtime.preprocess`：裁剪后到模型固定输入尺寸的 resize/letterbox 策略。

完整图数据集也会生成：

```yaml
preprocess:
  input_roi:
    enabled: false
```

第三阶段 Runtime 尚未实现前，边缘端会忽略这段新增配置，现有推理流程不受影响。

## Web 展示

服务端的 batch、dataset、training job 和模型包列表会显示：

```text
inputROI=640x432@1280x720[320,144,960,576]
```

完整图显示：

```text
inputROI=full-frame
```
