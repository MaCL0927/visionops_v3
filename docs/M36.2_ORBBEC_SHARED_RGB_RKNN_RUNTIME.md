# M36.2：Orbbec 336L 共享 RGB 实时 RKNN 推理

## 1. 阶段范围

M36.2 只验证以下实时链路：

```text
Orbbec Gemini 336L
  -> SDK Bridge :18182
  -> /visionops_orbbec336l_rgb
  -> C++ RKNN Runtime :28081
  -> segmentation inference_result
```

本阶段不读取深度、不执行 `foam_ring` / `ring_mouth` 配对、不运行三维几何和夹爪碰撞。RGB-D 同步缓存属于 M36.3。

当前实时基线继续使用：

```yaml
postprocess:
  mask_decode_mode: legacy_proto
```

`ultralytics_highres` 保留为实验模式，不是 M36.2 的验收前提。

## 2. 本阶段修复

原共享内存读取函数已经等待 Bridge 发布新序列，但采集线程随后又按照 `camera_fps` 休眠一次。30 FPS 输入因此可能接近被限制为 15 FPS。

M36.2 改为：

- POSIX 共享内存读取成功时不做额外节流；
- HTTP Bridge 快照继续按照配置帧率节流；
- 共享内存临时失败并回退 HTTP 时，只对 HTTP 回退路径节流；
- 保留 Bridge 原始 RGB sequence，不再被 Runtime 请求 sequence 覆盖。

## 3. Runtime 传输诊断

`GET /api/runtime/status` 的 `frame_source` 新增：

```json
{
  "type": "shared_memory",
  "configured_transport": "posix_shared_memory",
  "transport": "posix_shared_memory",
  "fallback_active": false,
  "shared_memory_sequence": 1234,
  "shared_memory_retry_count": 0,
  "shared_memory_fallback_count": 0,
  "last_transport_switch_timestamp_ms": 1780000000000,
  "capture_ms_latest": 1.2,
  "decode_ms_latest": 0.0
}
```

字段含义：

- `configured_transport`：启动时要求的传输方式；
- `transport`：最新帧实际采用的传输方式；
- `fallback_active=true`：共享内存当前不可用，正在使用 `http_jpeg_fallback`；
- `shared_memory_retry_count`：复制期间 sequence 变化而重试的次数；
- `shared_memory_fallback_count`：通过 HTTP 回退成功获取的帧数；
- `capture_ms_latest`：后台采集线程最近一次取帧耗时；
- `decode_ms_latest`：最近一次 JPEG 解码耗时；共享内存正常时应为 0。

旧字段 `transport` 被保留，但现在报告真实的活动传输方式，不再在 HTTP 回退时错误显示为 `posix_shared_memory`。

## 4. 启动

先完整清理构建：

```bash
cd /opt/visionops_v3
bash scripts/rebuild_runtime_rknn_clean.sh
```

确认 336L Bridge：

```bash
curl -s http://127.0.0.1:18182/health | python3 -m json.tool
ls -lh /dev/shm/visionops_orbbec336l_rgb
```

启动泡沫圆环 Runtime：

```bash
cd /opt/visionops_v3
bash production/foam_ring_grasp/scripts/start_rgb_runtime.sh \
  /opt/visionops_v3/models/rk3576-001_ring_seg_20260729_100731
```

也可使用通用脚本。`start_runtime.sh` 现在会读取 `active_camera.json`：

- `orbbec336l` 自动使用 `shared_memory`；
- `hp60c` 自动使用 `hp60c_bridge`；
- 可通过 `VISIONOPS_FRAME_SOURCE` 显式覆盖。

## 5. 手工检查

启动预览线程：

```bash
curl -s -X POST http://127.0.0.1:28081/api/runtime/start_preview |
  python3 -m json.tool
```

检查状态：

```bash
curl -s http://127.0.0.1:28081/api/runtime/status |
  python3 -m json.tool
```

正常状态应包含：

```text
loaded_model.task_type = segmentation
frame_source.type = shared_memory
frame_source.configured_transport = posix_shared_memory
frame_source.transport = posix_shared_memory
frame_source.fallback_active = false
frame_source.thread_alive = true
frame_source.stale = false
frame_source.shared_memory_sequence 持续增长
decode_ms_latest = 0
```

执行一次推理：

```bash
curl -s -X POST http://127.0.0.1:28081/api/runtime/infer_once |
  python3 -m json.tool
```

检查：

```text
status = ok
task_type = segmentation
capture_timestamp_ms > 0
detections[*].mask.source = proto
debug.rga_used = true
```

## 6. 自动验收

```bash
cd /opt/visionops_v3
python3 production/foam_ring_grasp/scripts/verify_rgb_runtime.py \
  --runtime-url http://127.0.0.1:28081 \
  --bridge-url http://127.0.0.1:18182 \
  --samples 20 \
  --report /tmp/m36_2_report.json
```

默认不允许 HTTP 回退。若仅排查相机重连，可临时加入：

```bash
--allow-http-fallback
```

自动验收会检查：

- Runtime 加载的是 segmentation 模型；
- 配置和活动传输均为 POSIX 共享内存；
- 后台取流线程存活且帧未过期；
- `shared_memory_sequence` 在测试期间持续增加；
- 多次推理使用不同 `capture_timestamp_ms`；
- mask 来自 `proto`，未退化为 bbox；
- 输出 capture、decode、inference、postprocess、total 的 mean/p50/p95/max。

## 7. 相机断线与回退

共享内存不可用且允许回退时：

```text
configured_transport = posix_shared_memory
transport = http_jpeg_fallback
fallback_active = true
shared_memory_fallback_count 持续增加
decode_ms_latest > 0
```

共享内存恢复后 Runtime 会自动重新尝试并切回：

```text
transport = posix_shared_memory
fallback_active = false
decode_ms_latest = 0
```

M36.2 的正式验收要求正常运行时不依赖 HTTP 回退。

## 8. 验收边界

M36.2 完成不代表三维抓取完成。只有以下内容通过：

1. 336L Bridge 稳定发布实时 RGB；
2. Runtime 稳定读取共享内存；
3. RKNN segmentation 连续输出；
4. Runtime 可识别并报告共享内存/HTTP 回退切换；
5. 相机画面和 `capture_timestamp_ms` 持续刷新。

下一步 M36.3 再加入完整 D2C 深度共享内存和按时间戳匹配的 RGB-D 缓存。
