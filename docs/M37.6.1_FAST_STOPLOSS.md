# M37.6.1 快速止损

## 目标

M37.6.1 不改变分割模型、RGB-D 同步、机器人协议或 C++ RKNN Runtime。它只收紧 Python 在线几何分支的计算边界，解决现场回放中最明显的两类问题：

1. 浅/深点云质心差（depth-gradient）错误否决残差良好的侧躺圆环，导致连续尝试多个实例；
2. `local_accurate` 单次可能额外消耗约十余秒，仍无法稳定挽救不确定姿态。

本版本是 M38 可见表面分支重构前的止损版本，不宣称解决完全侧躺圆环的单视角姿态歧义。

## 修改内容

### 1. depth-gradient 改为纯诊断证据

生产配置：

```yaml
side_ring_template:
  multi_surface_depth_gradient_weight: 0.0
  multi_surface_depth_gradient_hard_reject_enabled: false
```

效果：

- depth-gradient 不再参与轴线候选排序；
- 即使 `depth_gradient_axis_error_deg` 超过旧阈值，也不会产生 `axis_disagrees_with_depth_gradient` 拒绝；
- 仍保留 `depth_gradient_support`、`depth_gradient_axis_error_deg`；
- 超阈值时新增诊断标记 `axis_disagrees_with_depth_gradient_diagnostic`；
- 结果新增 `depth_gradient_policy`，明确当前权重与硬拒绝状态。

旧行为仍可通过显式设置以下字段恢复，便于离线对照：

```yaml
side_ring_template:
  multi_surface_depth_gradient_hard_reject_enabled: true
```

### 2. 禁用在线 local_accurate

生产配置：

```yaml
hybrid_grasp:
  bounded_refinement:
    maximum_accurate_refinements_per_trigger: 0
```

效果：

- 在线路径只保留轻量预筛选、`screen` 和延迟 `final_verify`；
- 不再触发 `search_profile=local_accurate`；
- `side_ring_branch.accurate_refinement_count` 应恒为 0；
- 保存的 RGB-D 数据仍可离线调用拟合脚本进行分析。

代码默认值也改为 0，避免缺少 YAML 字段时意外恢复长耗时路径。

### 3. M36 姿态冲突改为显式分支转交

生产配置：

```yaml
pose:
  pose_conflict_policy: fallback_to_m37
  pose_conflict_hard_reject_enabled: false
```

当 mouth 椭圆法向与局部深度平面明显冲突时：

- M36 不强行选取其中一个法向输出抓取；
- 该配对结果标记 `pose_conflict_fallback_to_m37`；
- `pose.pose_conflict_signals` 保留具体冲突原因；
- `pose.handoff_to_m37=true`；
- 已配对 mouth 继续作为 M37.6 的软端面约束；
- 场景结果新增 `m36_pose_conflict_handoff_count`。

支持三种策略：

- `hard_reject`：兼容 M37.5 原行为；
- `fallback_to_m37`：生产默认；
- `warn_only`：仅用于离线实验，不建议现场直接使用。

## 预期效果

针对已提供的 M37.6 回放，以下候选之前主要因 depth-gradient 被拒绝：

- `1785918527894`：实例 0、1；
- `1785918563998`：实例 0、2；
- `1785918911078`：实例 1、2、0、3、8。

M37.6.1 会让这些候选进入原有 `final_verify` 安全门限，而不是被一个不可靠的 depth-gradient 直接否决。部分场景可能因此增加 `final_verify` 次数；本版本真正确定的耗时止损来自彻底关闭在线 `local_accurate`，不是保证每一帧都减少 screen/final 次数。

同机离线回放结果显示：

- `1785918446926`：原版输出已知错误的实例 4；M37.6.1 不再输出目标；
- `1785918501957`：仍由 M36 正常输出实例 9；
- `1785918527894`：仍能输出实例 2；
- `1785918563998`：原版在一次 local_accurate 后输出已知错误的实例 7；M37.6.1 不再输出目标；
- `1785918911078`：两版均无目标，但 M37.6.1 的 local_accurate 次数由 1 降为 0。

这些是开发机离线回放结果，不代表 RK3576 真机延迟。真机部署后需要重新统计 `geometry_ms`、`m37_final_validation_count` 和 `m37_local_accurate_ms`。

注意：取消错误拒绝并不等于姿态一定正确。完全侧躺圆环仍存在单视角不可观测问题，因此 M37.6.1 宁可把明显不稳定的结果判为无目标；M38 将改为按可见表面直接估计局部几何。

## 验证

```bash
cd /opt/visionops_v3

python3 -m pytest -q \
  tests/unit/test_foam_ring_m3761_stoploss.py \
  tests/unit/test_foam_ring_hollow_multisurface_m376.py \
  tests/unit/test_foam_ring_hybrid_m37_3.py

python3 -m py_compile \
  production/foam_ring_grasp/tasks/foam_ring_grasp_vision/geometry.py \
  production/foam_ring_grasp/tasks/foam_ring_grasp_vision/hybrid_grasp.py \
  production/foam_ring_grasp/tasks/foam_ring_grasp_vision/side_ring_template.py
```

重启在线服务：

```bash
cd /opt/visionops_v3
pkill -f 'production.foam_ring_grasp.tasks.foam_ring_grasp_vision.service' || true
find production/foam_ring_grasp -type d -name '__pycache__' -prune -exec rm -rf {} +
bash production/foam_ring_grasp/scripts/start_online_service.sh
```

检查配置是否生效：

```bash
grep -nE \
  'pose_conflict_policy|maximum_accurate_refinements_per_trigger|multi_surface_depth_gradient_(weight|hard_reject_enabled)' \
  production/foam_ring_grasp/config/line.yaml
```

期望值：

```text
pose_conflict_policy: fallback_to_m37
maximum_accurate_refinements_per_trigger: 0
multi_surface_depth_gradient_weight: 0.0
multi_surface_depth_gradient_hard_reject_enabled: false
```

## 回滚

若需要恢复 M37.6 行为：

```yaml
pose:
  pose_conflict_policy: hard_reject
  pose_conflict_hard_reject_enabled: true

hybrid_grasp:
  bounded_refinement:
    maximum_accurate_refinements_per_trigger: 1

side_ring_template:
  multi_surface_depth_gradient_weight: 0.08
  multi_surface_depth_gradient_hard_reject_enabled: true
```
