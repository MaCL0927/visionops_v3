# M36.4 — Runtime polygon + exact RGB-D one-shot geometry

M36.4 connects the validated M36.2/M36.3 paths to the existing foam-ring
`analyze_scene()` implementation.  It is intentionally a single diagnostic
transaction, not the continuous M36.5 service and not a robot-ready output.

## Data contract

1. The C++ Runtime reads Orbbec RGB through POSIX shared memory and returns an
   RKNN segmentation result.
2. `capture_timestamp_ms` must exactly match an entry in `RgbdFrameCache`.
3. Only `mask.source=proto` polygons may enter geometry. `bbox_fallback` is
   rejected.
4. The current box model was calibrated in Runtime input-ROI coordinates.  The
   exact full-frame RGB-D is therefore cropped to `input_roi.pixel_xyxy`, and
   intrinsics are transformed with `cx -= roi_x1`, `cy -= roi_y1`.
5. Any timestamp, resolution, D2C, calibration, ROI or mask contract mismatch
   fails the transaction. No latest/nearest depth fallback is permitted.

## Run

Keep the Orbbec Bridge and foam-ring Runtime running, then execute:

```bash
cd /opt/visionops_v3
bash production/foam_ring_grasp/scripts/run_online_geometry_once.sh
```

Equivalent Python command:

```bash
cd /opt/visionops_v3
python3 -m \
  production.foam_ring_grasp.tasks.foam_ring_grasp_vision.online_validate \
  --config production/foam_ring_grasp/config/line.yaml \
  --runtime-url http://127.0.0.1:28081 \
  --output /opt/visionops_v3/data/foam_ring_online_geometry
```

## Output

Each run creates a timestamp directory:

```text
data/foam_ring_online_geometry/<capture_timestamp_ms>/
├── exact_rgb.png
├── exact_depth.png
├── depth_colormap.jpg
├── runtime_inference_result.json
├── online_geometry_result.json
└── online_geometry_overlay.jpg
```

`exact_rgb.png` and `exact_depth.png` are the geometry ROI, not independently
captured files. They originate from the same exact full-frame RGB-D entry and
use the same ROI transform as the masks and intrinsics.

The result remains:

```json
{
  "robot_ready": false
}
```

M36.4 does not apply hand-eye calibration, robot reachability, trigger
protocol, or motion execution.

## Acceptance

A successful run prints:

```text
[PASS] M36.4 one-shot exact RGB-D online geometry completed.
```

Review:

- `timestamp_delta_ms == 0`
- geometry size is `528x455` for the current Runtime ROI
- transformed intrinsics are approximately `cx=261.818`, `cy=197.640`
- proto masks were accepted and bbox fallbacks were rejected
- `matched_pairs`, `eligible_count` and rejection reasons are plausible
- overlay is aligned with the exact RGB and depth
- `robot_ready` remains false
