# M37.4 Depth-Layered Grasp Ordering and Bounded Accurate Refinement

## Goal

M37.4 fixes two production issues observed across 16 sequential grasp triggers:

1. confidence-first / branch-first selection could choose a deeper ring before a
   physically exposed upper-layer ring;
2. one uncertain M37 fast fit immediately launched a full 320-direction accurate
   global search, and multiple candidates could each pay this cost in one trigger.

The online trigger API is unchanged. One segmentation result and one exact RGB-D
frame are shared by all selection stages.

## Selection order

1. For every `foam_ring`, erode its mask, remove a dilated paired `ring_mouth`
   region when present, and compute robust front-surface depth using P25.
2. Sort valid candidates by this depth and form layers with a 30 mm tolerance.
3. Process layers from nearest to farthest.
4. Inside one layer, try M36 mouth-visible candidates first.
5. If M36 has no valid candidate in that layer, try unmatched M37 candidates in
   surface-depth order using the fast profile.
6. Return immediately on the first fast-accepted M37 candidate.
7. If every fast candidate in the layer is uncertain, refine only the best fast
   seed once using local angular search. The global direction search is not
   repeated.
8. Continue to the next depth layer only when the current layer cannot produce a
   candidate.

## Bounded refinement

The online path explicitly calls:

- `search_profile=fast` for candidate screening;
- `search_profile=local_accurate` for at most one warm-start refinement.

`local_accurate` starts from `axis_toward_camera` returned by the best fast fit,
uses the larger point sample, and searches only `[4.0, 1.5, 0.5]` degrees around
that axis. It never performs the 320-direction global search.

Standalone/offline `search_profile=auto` remains backward compatible and can
still run the historical full accurate fallback for diagnostic comparison.

## Main configuration

```yaml
hybrid_grasp:
  depth_layering:
    enabled: true
    layer_tolerance_mm: 30.0
    surface_percentile: 25.0
    mask_erode_px: 3
    mouth_exclusion_dilate_px: 2
    sample_stride: 2

  bounded_refinement:
    fast_first_enabled: true
    maximum_accurate_refinements_per_trigger: 1

side_ring_template:
  fast_maximum_fit_points: 700
  fast_global_maximum_fit_points: 400
  fast_global_axis_samples: 80

  local_accurate_maximum_fit_points: 1200
  local_accurate_refine_angles_deg: [4.0, 1.5, 0.5]
  local_accurate_refine_radial_steps: 3
  local_accurate_refine_azimuth_steps: 16
  local_accurate_fixed_radius_iterations: 12
```

## New result fields

- `scene.depth_layering.layers`
- `scene.depth_layering.candidates`
- `scene.depth_layering.selected_layer_index`
- `scene.depth_layering.selected_surface_depth_mm`
- `scene.depth_layering.selected_depth_rank`
- `scene.side_ring_branch.fast_attempt_count`
- `scene.side_ring_branch.accurate_refinement_count`
- `scene.side_ring_branch.global_accurate_search_used`
- `scene.m37_4_timing`

The debug overlay labels every ring as `L<layer> z=<surface-depth-mm>`.

## Validation

Replay a saved set of debug bundles:

```bash
python3 production/foam_ring_grasp/scripts/replay_m37_4_result_set.py \
  /path/to/foam_ring_online_geometry \
  --output /tmp/m37_4_replay
```

Summarize one live trigger:

```bash
python3 production/foam_ring_grasp/scripts/summarize_hybrid_timing.py
```

The acceptance conditions are:

- selected targets come from the nearest layer that has any valid grasp;
- `global_accurate_search_used` is always `false` in the online hybrid path;
- `accurate_refinement_count <= 1` for every trigger;
- lower layers are not evaluated after a valid upper-layer result is found.
