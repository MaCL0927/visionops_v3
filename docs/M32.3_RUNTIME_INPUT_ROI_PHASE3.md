# VisionOps v3 M32.3：Runtime 高性能输入 ROI

M32.3 完成 ROI 方案第三阶段。边缘端 C++ Runtime 读取模型包中的
`preprocess.input_roi`，在现有完整相机帧上直接裁剪模型输入区域，然后执行
letterbox、RKNN 推理和完整图坐标恢复。

本阶段不修改 M32.1 的采集 ROI，也不修改原有 `/api/runtime/roi` 结果过滤 ROI。
三者仍保持独立语义：

```text
capture_roi                 采集时裁剪并保存数据
model.yaml input_roi        Runtime 实际模型输入裁剪
/api/runtime/roi            推理后按完整图坐标过滤结果
```

## 1. 实际数据流

```text
Camera Bridge 完整 RGB 帧
        ↓
现有共享内存 / HTTP / V4L2 帧源
        ↓
Runtime 读取同一帧，不增加第二次取图
        ↓
解析 model.yaml.preprocess.input_roi
        ↓
RGA：source ROI → 最终模型输入 canvas
     一次完成 crop + resize
CPU：只初始化 letterbox pad
        ↓
RKNN 推理
        ↓
检测框、OBB 四点、分割坐标恢复到完整图
        ↓
原有结果 ROI 过滤
        ↓
标准 inference_result / 业务 App / 机器人
```

正式 RGA 路径不会先创建一张 ROI 中间图，也不会重新请求 Bridge 快照或重新
JPEG 解码。Runtime 仍沿用原有完整帧缓存；M32.3 没有把 Camera Bridge 与某个
任务的 ROI 绑定。

`--preprocess-backend auto` 下，RGA 可用时优先使用融合路径；RGA 调用失败时回退
CPU。`--preprocess-backend rga` 下不允许静默回退，失败会返回明确错误。

## 2. 模型 YAML

M32.2 生成的配置可直接生效：

```yaml
runtime:
  preprocess: letterbox
  color: rgb

preprocess:
  input_roi:
    enabled: true
    coordinate_space: runtime_snapshot
    source_resolution:
      width: 1280
      height: 720
    pixel_xyxy: [850, 490, 1277, 719]
    normalized_xyxy: [0.6640625, 0.680555555556, 0.99765625, 0.998611111111]
    crop_resolution:
      width: 427
      height: 229
    resize_mode: letterbox
    pad_value: 114
```

坐标约定：

- `pixel_xyxy` 使用 `[x0, y0, x1, y1]`；
- `x1/y1` 是右下角排他边界；
- 上例实际裁剪宽高为 `1277-850=427`、`719-490=229`；
- 坐标基于 Runtime/Bridge 输出的完整 `1280×720` 图像；
- 旧模型没有该字段或 `enabled: false` 时继续使用完整图推理。

Runtime 加载模型时校验像素坐标、归一化坐标、源分辨率、裁剪尺寸、缩放方式和
pad 值。配置错误会进入 degraded 状态，而不是静默改用完整图。

OBB 模型启用输入 ROI 时要求 `resize_mode: letterbox`。非等比例 resize 会改变旋转
矩形几何和角度，因此 Runtime 会拒绝该组合。

## 3. 上述 ROI 到 640×640 的变换

```text
ROI                 427×229
模型输入             640×640
scale               min(640/427, 640/229)
                    = 1.498829...
缩放后              640×343
水平 padding         0
垂直 padding         约 148.5 像素/边
```

RGA 源矩形：

```text
x=850, y=490, width=427, height=229
```

RGA 目标矩形位于最终 `640×640` RGB canvas 中：

```text
x=0, y=148, width=640, height=343
```

canvas 其余区域用 `pad_value=114` 初始化。裁剪和缩放由一次 `improcess` 完成，
不会生成 `427×229` 的中间 `cv::Mat` 或 `ImageBuffer`。

CPU 回退路径也直接从完整图 ROI 采样到最终模型 canvas，不创建中间 ROI 图，但
性能仍低于 RGA，生产环境应确认 `preprocess_backend_active=rga`。

## 4. 完整图坐标恢复

模型输出首先消除 letterbox，再加 ROI 左上角偏移：

```text
x_full = (x_model - pad_x) / scale_x + roi_x
 y_full = (y_model - pad_y) / scale_y + roi_y
```

上例为：

```text
x_full = x_model / 1.498829... + 850
 y_full = (y_model - 148.5) / 1.498829... + 490
```

输出会限制在实际输入 ROI 和完整图范围内。以下字段继续使用完整图坐标，不修改
协议字段名：

- detection `bbox_xyxy`、`center_xy`；
- OBB `cx/cy/w/h/angle_deg/points`；
- segmentation bbox 和 polygon；
- 洗衣液任务的 `center_px`、`object_center_px`、`grasp_point_px`、`obb_points`。

输入 ROI 只做平移和等比例 letterbox 时，OBB 角度不变。OBB 后处理会先恢复四个
角点，再由完整图角点重新计算中心、宽高和角度。

因此机器人端仍把 `image.width/height` 视为完整视频尺寸，原有像素手眼标定和视频
叠加不需要改协议。

## 5. 分辨率兼容规则

1. 当前帧与 `source_resolution` 完全一致：优先使用 `pixel_xyxy`；
2. 尺寸不同但宽高比一致：使用 `normalized_xyxy` 重新计算 ROI，并在结果中标记
   `scaled_from_normalized: true`；
3. 宽高比不同：拒绝推理并返回 `INPUT_ROI_SOURCE_ASPECT_MISMATCH`；
4. 尺寸不同且没有归一化坐标：返回 `INPUT_ROI_SOURCE_RESOLUTION_MISMATCH`。

例如采集为 `1280×720`，Runtime 改为 `640×360` 时可以按归一化坐标缩放；改为
`640×480` 时不会静默运行，因为视野比例已经变化。

## 6. 原有结果 ROI 保留

处理顺序为：

```text
input_roi 裁剪模型输入
        ↓
模型推理
        ↓
恢复完整图坐标
        ↓
/api/runtime/roi 结果过滤
```

`--roi-config`、`GET /api/runtime/roi`、`POST /api/runtime/roi` 的字段和行为没有变化。
结果 ROI 不会影响模型计算量；模型输入 ROI 才会影响送入模型的图像区域。

## 7. Runtime 状态和耗时

`GET /api/runtime/status` 的以下位置会返回模型配置：

```text
loaded_model.input_roi
preprocess.input_roi
```

`POST /api/runtime/infer_once` 新增：

```text
input_roi                         本帧实际生效区域
timing.input_roi_resolve_ms       ROI 解析耗时
timing.crop_resize_ms             裁剪和缩放耗时
timing_detail.*                   同名细分耗时
```

真实 RKNN 结果的 `debug` 还会返回：

```text
preprocess_backend_active
rga_used
rga_fused_crop_resize
rga_mode                          ROI 模型应为 crop_resize_rgb
input_roi
letterbox.scale / scale_x / scale_y / pad_x / pad_y
preprocess_warning
```

生产环境重点检查：

```text
preprocess_backend_active = rga
rga_used = true
rga_fused_crop_resize = true
rga_mode = crop_resize_rgb
```

## 8. LB3576 构建和部署

M32.3 修改了 C++ Runtime，覆盖代码后必须重新编译。洗衣液 launcher 默认使用：

```text
/opt/visionops_v3/build-rknn/edge/runtime_cpp/visionops_runtime_mock
```

推荐命令：

```bash
cd /opt/visionops_v3
rm -rf build-rknn

cmake -S . -B build-rknn \
  -DCMAKE_BUILD_TYPE=Release \
  -DVISIONOPS_ENABLE_RKNN=ON \
  -DVISIONOPS_ENABLE_OPENCV=ON \
  -DVISIONOPS_ENABLE_RGA=ON \
  -DVISIONOPS_RKNN_INCLUDE_DIR=/usr/include \
  -DVISIONOPS_RKNN_LIBRARY=/usr/lib/librknnrt.so \
  -DVISIONOPS_RGA_INCLUDE_DIR=/usr/include \
  -DVISIONOPS_RGA_LIBRARY=/usr/lib/librga.so

cmake --build build-rknn -j$(nproc)
```

实际 SDK 路径不同的话先查找：

```bash
find /usr /opt -name rknn_api.h -o -name librknnrt.so -o -name im2d.hpp -o -name librga.so 2>/dev/null
```

重启洗衣液服务：

```bash
sudo systemctl restart visionops-v3-detergent-grasp-runtime.service
sudo systemctl restart visionops-v3-detergent-grasp-app.service
sudo systemctl restart visionops-v3-detergent-grasp-collector.service
```

检查：

```bash
systemctl status visionops-v3-detergent-grasp-runtime.service --no-pager
journalctl -u visionops-v3-detergent-grasp-runtime.service -n 100 --no-pager

curl -s http://127.0.0.1:28087/api/runtime/status | python3 -m json.tool
curl -s -X POST http://127.0.0.1:28087/api/runtime/infer_once | python3 -m json.tool
```

端口以 `/etc/visionops_v3/detergent_grasp.yaml` 为准。

## 9. 性能验证

先预热，再统计 50 帧：

```bash
cd /opt/visionops_v3
python3 tools/benchmark_runtime.py \
  --runtime-url http://127.0.0.1:28087 \
  --warmup 10 \
  --count 50 \
  --output /tmp/detergent_roi_runtime_benchmark.json
```

对比时应分别记录：

```text
完整图模型 input_size=1280×1280 的 inference_ms
ROI 模型 input_size=640×640 的 inference_ms
ROI 模型的 crop_resize_ms
总 total_ms 和实际 inference_fps
```

ROI 本身主要减少无关视野；NPU 计算量的核心下降来自模型固定输入由 1280 降到
640。若仍导出 1280×1280 模型，即使启用 ROI，NPU 仍计算 1280×1280 tensor，
不会获得预期的主要收益。

## 11. 本阶段边界

M32.3 已完成 Runtime 裁剪、推理和完整图坐标恢复。完整视频流仍保持不变。
下一阶段 Web 可视化可以把 `input_roi` 画成独立边框，并增加“完整图 / 模型实际输入图”
切换；这些前端功能不属于 M32.3。
