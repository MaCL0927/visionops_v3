# M32.4.1 model.yaml 设置保存兼容修复

## 问题

M32.4 的算法设置接口使用 `yaml.safe_load` + `yaml.safe_dump` 重写完整的
`model.yaml`。虽然重写后的文件仍是合法 YAML，但会改变原文表示方式：

- `input_size: [640, 640]` 被展开成块列表；
- `pixel_xyxy`、`normalized_xyxy` 被展开成块列表；
- `20260725_165208` 会被 YAML 1.1 当作带下划线的整数，保存后变成
  `20260725165208`；
- 阈值读取只检查顶层，未识别 `postprocess.conf_threshold` 和
  `postprocess.iou_threshold`，因此会额外追加顶层 `score_threshold`、
  `nms_threshold`；
- M32.3 Runtime 的轻量 YAML 解析器只支持 input ROI 内联四元素数组，遇到
  PyYAML 块列表时在 `pixel_xyxy` 处拒绝切换模型。

## 修复

### Collector Web

算法设置保存改为文本级原位更新：

1. 优先读取 `postprocess` 下的现有阈值；
2. 只替换阈值所在行的数值；
3. 不重新序列化整个 YAML；
4. 保留字段顺序、注释、内联数组、数字字符串和换行格式；
5. 对历史文件中同时存在的嵌套与顶层阈值同步更新，避免 Runtime 读取到不一致值；
6. 缺失阈值时在 `postprocess` 下添加规范字段。

任务支持范围：

- classification：`conf/score`；
- detection：`conf/score + iou/nms`；
- segmentation：`conf/score + iou/nms`；
- obb：`conf/score + iou/nms`。

### C++ Runtime

轻量 YAML 解析器同时接受下面两种 input ROI 写法：

```yaml
pixel_xyxy: [850, 490, 1277, 719]
```

以及历史 PyYAML 产生的：

```yaml
pixel_xyxy:
- 850
- 490
- 1277
- 719
```

`normalized_xyxy` 同样兼容两种形式。这样已被旧设置页重排过的模型包也能继续加载。

## 更新影响

本版本修改了 C++ Runtime，因此在边缘端覆盖代码后必须重新编译并重启 Runtime。
模型文件、RKNN 推理逻辑、输入 ROI 几何和机器人协议均未改变。
