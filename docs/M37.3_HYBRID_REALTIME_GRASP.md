# M37.3 Hybrid Real-Time Foam-Ring Grasp

M37.3 keeps the M36.5 persistent trigger API and automatically selects the
geometry branch. The trigger request never specifies the ring posture.

## One-trigger flow

1. Runtime performs one RKNN segmentation inference.
2. The result is matched to one exact RGB-D cache entry by
   `capture_timestamp_ms`.
3. M36 mouth-visible geometry runs first.
4. If M36 returns a valid rim-pinch candidate, it is returned immediately and
   M37 is not executed.
5. Otherwise, only M36-unmatched `foam_ring` instances enter M37.2, ordered by
   segmentation confidence. The first eligible near-visible-crown fit is
   returned immediately.

Both branches use the same segmentation instances, depth image and intrinsics.
There is no second Runtime request and no nearest-depth fallback.

## Trigger

```bash
curl -s -X POST http://127.0.0.1:19213/api/foam_ring/infer_once \
  -H 'Content-Type: application/json' \
  -d '{"request_id":"robot-000001","wait":true,"save_debug":false}' |
  python3 -m json.tool
```

The response field `selected_grasp_branch` is one of:

- `m36_mouth_visible_rim_pinch`
- `m37_side_ring_near_visible_crown`
- `none`

M37 candidates contain `grasp_point_camera_mm`, `grasp_point_uv`,
`axis_toward_camera`, near/far opening centers and fit quality. They remain
`robot_ready=false` until gripper-frame construction, hand-eye transform and
robot reachability are implemented.

## Timing

The full result includes:

- `scene.hybrid_grasp.timing_ms.m36_branch_ms`
- `scene.hybrid_grasp.timing_ms.m37_candidate_filter_sort_ms`
- `scene.hybrid_grasp.timing_ms.m37_fit_loop_ms`
- `scene.hybrid_grasp.timing_ms.m37_evaluated_instance_total_ms`
- `scene.hybrid_grasp.timing_ms.total_ms`

Use:

```bash
python3 production/foam_ring_grasp/scripts/summarize_hybrid_timing.py
```

## Compatibility

The HTTP paths, reliable `request_id` queue, exact RGB-D matching and debug
capture behavior are unchanged from M36.5. Setting `hybrid_grasp.enabled=false`
restores the M36-only online behavior.
