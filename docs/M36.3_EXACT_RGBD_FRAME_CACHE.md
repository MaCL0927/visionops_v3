# M36.3：Runtime RGB 时间戳与 D2C 深度精确匹配

## 1. 阶段目标

M36.3 在已经通过验收的 M36.2 实时 RGB 共享内存链路上增加一个短时 RGB-D 缓存：

```text
Orbbec 336L 同一 SDK FrameSet
  ├─ /visionops_orbbec336l_rgb
  └─ /visionops_orbbec336l_depth
              ↓
      RgbdFrameCache（最近 12 帧）
              ↓
Runtime inference_result.capture_timestamp_ms
              ↓ exact lookup
      同一时间戳的 D2C 深度与内参
```

该阶段只验证同步和缓存，不执行圆环配对、平面、轴线、抓取点或碰撞计算。

## 2. 为什么必须缓存

RKNN 推理与分割后处理约需几十毫秒。Runtime 返回结果时，Bridge 已经可能发布了后续一到两帧。如果业务代码在结果返回后直接读取“最新深度”，就会形成：

```text
旧 RGB 掩膜 + 新 Depth
```

这会让掩膜边缘、平面拟合、轴线和碰撞点云错位。Bridge 的共享内存只有双缓冲，且 header 只记录当前活动帧的时间戳，因此必须在推理返回前持续复制并保存一个短历史。

## 3. 同步安全契约

`RgbdFrameCache` 仅缓存满足以下条件的帧：

1. RGB 与 Depth header 协议有效；
2. 两者均处于 running 状态；
3. Depth 已完成 D2C 对齐并具有有效内参；
4. RGB 与 Depth 分辨率完全一致；
5. 复制前后 sequence、active buffer 和 timestamp 未变化；
6. RGB `timestamp_epoch_ms == Depth timestamp_epoch_ms`。

Runtime 结果只能通过：

```python
frame = cache.get_exact(result["capture_timestamp_ms"])
```

获得深度。设计上不提供 nearest/latest 自动回退。找不到精确帧时，本次三维计算必须失败并返回 `DEPTH_NOT_MATCHED`，不能静默使用相邻帧。

## 4. 配置

配置位于：

```text
production/foam_ring_grasp/config/line.yaml
```

```yaml
online_rgbd:
  enabled: true
  shared_rgb_name: /visionops_orbbec336l_rgb
  shared_depth_name: /visionops_orbbec336l_depth
  cache_frames: 12
  max_age_ms: 2000
  poll_interval_ms: 1.0
  exact_match_timeout_ms: 500
  cache_rgb: true
  require_exact_timestamp: true
  allow_nearest_fallback: false
```

在 1280×720 下，一帧 RGB 加 uint16 Depth 约 4.6 MB，12 帧约占 55 MB。`cache_rgb=false` 可减少约 33 MB，但 M36.4 将无法使用精确时刻的 RGB 做叠加图。

## 5. 真机验收

先保持 M36.2 Runtime 和 Bridge 正常运行：

```bash
cd /opt/visionops_v3

bash production/foam_ring_grasp/scripts/start_rgb_runtime.sh \
  /opt/visionops_v3/models/rk3576-001_ring_seg_20260729_100731
```

再执行：

```bash
python3 production/foam_ring_grasp/scripts/verify_rgbd_cache.py \
  --samples 20 \
  --report /tmp/m36_3_report.json
```

可额外保存一组精确同步的 NumPy 文件：

```bash
python3 production/foam_ring_grasp/scripts/verify_rgbd_cache.py \
  --samples 20 \
  --save-sample-dir /tmp/m36_3_sample \
  --report /tmp/m36_3_report.json
```

## 6. 验收标准

正式通过要求：

- Bridge `shared_rgb_ready=true`；
- Bridge `shared_depth_ready=true`；
- Bridge `shared_depth_calibration_ready=true`；
- RGB/Depth 均为 1280×720；
- Cache 配对速率不低于 20 FPS；
- 每个 Runtime `capture_timestamp_ms` 都能精确命中缓存；
- `timestamp_delta_ms=0`；
- 深度有效像素比例大于 0；
- 不使用 HTTP 深度回退，不使用 nearest/latest 深度替代。

通过后，下一阶段 M36.4 才把 Runtime polygon 转为 `SegmentationInstance`，并将匹配帧送入现有 `analyze_scene()`。

## 7. Bridge 重启处理

Reader 每次访问会比较 `/dev/shm` 当前 inode、大小与已映射对象。Bridge 删除并重建共享内存后，Reader 会自动关闭旧 mmap 并重新打开新对象。缓存不会返回重启前的过期帧作为新结果。
