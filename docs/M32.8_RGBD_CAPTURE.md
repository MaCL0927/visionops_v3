# M32.8 同步 RGB-D 采集与上传

## 功能

拍照采集页新增“同步保存深度”开关，默认不勾选。

- 未勾选：保持旧行为，只保存 RGB。
- 勾选：手动拍照以及新启动的定时采图保存同一帧的 RGB、16 位深度和 meta。
- 开启采集 ROI 时，RGB 与深度使用同一组 normalized ROI 裁剪。
- 上传包自动包含 `images/`、`depth/`、`meta/`。
- 删除 RGB 时同步删除同名 depth/meta。

## 保存目录

```text
/opt/visionops_v3/data/images/<capture_id>.jpg
/opt/visionops_v3/data/depth/<capture_id>.png
/opt/visionops_v3/data/meta/<capture_id>.json
/opt/visionops_v3/data/upload_packages/*.tar.gz
```

深度文件为 OpenCV 可直接读取的 `uint16` PNG，单位毫米：

```python
import cv2

depth_mm = cv2.imread("depth.png", cv2.IMREAD_UNCHANGED)
assert depth_mm.dtype.name == "uint16"
```

## 同步保证

Orbbec Bridge 已经把同一个 SDK `FrameSet` 中的 RGB 和 D2C 深度发布到两个 POSIX shared-memory 双缓冲区，并为二者写入相同的 `timestamp_epoch_ms`。

Collector 的保存规则：

1. 分别用 sequence counter 校验 RGB 和 Depth 读取期间没有被覆盖；
2. 仅接受 `rgb.timestamp_epoch_ms == depth.timestamp_epoch_ms` 的帧对；
3. 校验深度已标定、对齐且帧龄未超过 1500 ms；
4. 无法验证同步时本次采集报错，不回退为两个 HTTP 快照拼接。

默认共享内存：

```text
/dev/shm/visionops_orbbec336l_rgb
/dev/shm/visionops_orbbec336l_depth
```

可用环境变量覆盖：

```bash
VISIONOPS_CAPTURE_SHARED_RGB_PATH=/dev/shm/visionops_orbbec336l_rgb
VISIONOPS_CAPTURE_SHARED_DEPTH_PATH=/dev/shm/visionops_orbbec336l_depth
```

当前精确同步链路面向 `active_camera=orbbec336l`，包括通过该 Bridge 接入且能正常发布 shared RGB/depth 的 Orbbec 设备。HP60C Bridge 当前没有同等的共享帧同步契约，勾选时会明确报错而不会伪装成同步数据。

## meta 主要字段

```json
{
  "capture_id": "visionops_20260728_120000_123",
  "timestamp_epoch_ms": 1785200000123,
  "synchronized": true,
  "synchronization_mode": "posix_shared_memory_timestamp_match",
  "rgb": {
    "filename": "visionops_...jpg",
    "sequence": 100,
    "source_resolution": {"width": 640, "height": 480},
    "saved_resolution": {"width": 443, "height": 350}
  },
  "depth": {
    "filename": "visionops_...png",
    "encoding": "16UC1_PNG",
    "unit": "mm",
    "sequence": 100,
    "aligned_to_color": true,
    "intrinsics_source": {"fx": 0, "fy": 0, "cx": 0, "cy": 0},
    "intrinsics_saved": {"fx": 0, "fy": 0, "cx": 0, "cy": 0},
    "valid_pixel_ratio": 0.95
  }
}
```

当 ROI 只执行裁剪、不缩放时：`fx/fy` 不变，`cx/cy` 会减去深度 ROI 左上角坐标。

## 3576 部署

覆盖仓库后重启 Collector：

```bash
cd /opt/visionops_v3
systemctl list-units --type=service | grep -Ei 'visionops.*collector'
# 选择当前任务对应的 Collector，例如：
sudo systemctl restart visionops-v3-carton-palletizing-collector.service
sudo journalctl -u visionops-v3-carton-palletizing-collector.service -f -o cat
```

确认 Orbbec shared memory：

```bash
ls -lh /dev/shm/visionops_orbbec336l_rgb \
       /dev/shm/visionops_orbbec336l_depth
curl -s http://127.0.0.1:18182/health | python3 -m json.tool
```

## 验收

1. 打开“采集上传 → 拍照采集”。
2. 不勾选开关拍一次，确认只增加 `data/images` 文件。
3. 勾选“同步保存深度”再拍一次。
4. 检查三类同名文件：

```bash
find /opt/visionops_v3/data/{images,depth,meta} -maxdepth 1 -type f \
  -printf '%p %s bytes\n' | tail -n 20
```

5. 验证深度确实是 16 位：

```bash
cd /opt/visionops_v3
python3 - <<'PY'
import glob, cv2
p = sorted(glob.glob('data/depth/*.png'))[-1]
d = cv2.imread(p, cv2.IMREAD_UNCHANGED)
print(p, d.dtype, d.shape, int(d[d > 0].min()), int(d.max()))
PY
```

6. 点击上传后检查包内容：

```bash
PKG=$(ls -t /opt/visionops_v3/data/upload_packages/*.tar.gz | head -n1)
tar -tzf "$PKG" | grep -E '^(images|depth|meta)/|manifest.json'
```

7. 服务端处理后确认：

```bash
find /opt/visionops_v3/server_data/batches -path '*/raw/depth/*.png' | tail
find /opt/visionops_v3/server_data/batches -path '*/raw/meta/*.json' | tail
```
